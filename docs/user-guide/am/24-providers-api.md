# 24 · አቅራቢዎችና የAPI አስተዳደር

**ለማን፡** ለአገልግሎት አቅራቢ አስተዳደር ባለሙያዎች፣ ለውህደት (integration) አስተዳዳሪዎች።

**ዓላማ፡** ካፌቴሪያ፣ ትራንስፖርትና ሌሎች አገልግሎቶችን የሚሰጡ ድርጅቶች በአንድ መዝገብ እንዲኖሩ፣ የፖርታል ተጠቃሚዎቻቸው እንዲተዳደሩ፤ ውጫዊ ሥርዓቶች (ለምሳሌ የደመወዝ ሥርዓት) በ API በፈቃድ እንዲገናኙ።

## አቅራቢዎች

| ገጽ | ምን ያደርጋል |
|---|---|
| አቅራቢዎች | ድርጅቶች፡ ኮድ (በኮድ ደንብ)፣ ስም፣ የንግድ ፈቃድ፣ አድራሻ፣ የሚሰጡት አገልግሎቶች (ካፌቴሪያ/ትራንስፖርት)፣ ሁኔታ። |
| የአቅራቢ ተጠቃሚዎች (በአስተዳደር ምናሌ) | የአቅራቢው ሠራተኞች ወደ አቅራቢ ፖርታል የሚገቡባቸው መለያዎች። |

**አቅራቢ መመዝገብ**
1. አቅራቢዎች › አዲስ፡ መረጃውን ይሙሉ፣ አገልግሎቶችን ይምረጡ። "አስቀምጥ"።
2. የአቅራቢ ተጠቃሚዎች › አዲስ › አቅራቢውን ይምረጡ › ስም፣ ኢሜይል። ጊዜያዊ የይለፍ ቃል ይላካል፤ ተጠቃሚው የራሱን ፖርታል (ግብይቶች፣ ማወራረጃ፣ መገለጫ) ብቻ ያያል።

**አቅራቢን ማቆም (archive)**
- ሌላ ንቁ አገልግሎት የሚሰጥ አቅራቢ አይቆምም፤ መጀመሪያ አገልግሎቶቹን ይዝጉ። ክፍት ማወራረጃ ካለ ይጠናቀቅ።

## የAPI አስተዳደር

| ገጽ | ምን ያደርጋል |
|---|---|
| የAPI ደንበኞች | ውጫዊ ሥርዓት፡ ስም፣ ወሰኖች (scopes: ለምሳሌ ሠራተኛ ማንበብ፣ ተቋም ማንበብ)፣ የተቋም ወሰን፣ የ IP ገደብ፣ ቁልፍ። |
| Webhooks | ክስተት ሲከሰት (ሠራተኛ ተመዘገበ፣ ካርድ ታገደ) ወደ ውጫዊ አድራሻ የሚላክ የተፈረመ መልዕክት። |
| የAPI መዝገቦች | የእያንዳንዱ ጥሪ መዝገብ (ማን፣ መቼ፣ ምን፣ ውጤት)። |

**የAPI ደንበኛ መፍጠር**
1. የAPI አስተዳደር › አዲስ ደንበኛ፡ ስም፣ ባለቤት ተቋም፣ ወሰኖች (ዝቅተኛውን ብቻ)፣ የ IP ዝርዝር።
2. ቁልፉ **አንድ ጊዜ** ይታያል፤ ለደንበኛው በደህና መንገድ ይስጡ። ቢጠፋ "አዙር" (rotate)።
3. ሰነዱ፡ `docs/api-management-guide.md` እና የ OpenAPI ገጽ (`/api/v1/docs`)።

## ደንቦች

- ወሰኖች ከፈቃድ ካታሎጉ ጋር አንድ ናቸው፤ ደንበኛ ከተሰጠው ወሰን ውጭ ምንም አያነብም።
- የተቋም ወሰን ያለው ደንበኛ የዚያን ተቋም መረጃ ብቻ ያገኛል (fail-closed)።
- የ API መዝገቦች በተቀመጠው ጊዜ ይጸዳሉ (retention)።
- Webhook ፊርማው ካልተረጋገጠ ተቀባዩ መቀበል የለበትም፤ መመሪያው በሰነዱ አለ።
